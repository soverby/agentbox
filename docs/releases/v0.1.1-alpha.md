# agentbox 0.1.1-alpha

This release replaces 0.1.0. The 0.1.0 tree cannot build the agent image:
use 0.1.1-alpha.

## Fixes

- **Agent image builds from a clean clone.** `images/agent/versions.env`
  (the pinned tool versions) was not in the repository: the `*.env` ignore
  rule excluded it. It is now committed.
- **Linux: host tools can read the logs.** The egress, gate, and gateway log
  folders belonged to the container users, so the host CLI could not read
  them (`agentbox denied`, log rotation). The folders now also belong to
  your primary group (mode `2770`, setgid). Other users get no access.

## Security

- **Linux: more host folders are refused as mounts.** agentbox now refuses
  `/tmp`, `/run`, `/proc`, `/sys`, `/dev`, `/boot`, `/root`, `/snap`, and
  `/home` itself. Linux keeps live ssh-agent, gpg-agent, and rootless Docker
  sockets in `/tmp` and `/run/user/<uid>`. A mount of these folders would
  give the agent your host credentials.
- **CI actions are pinned by commit SHA** (`actions/checkout` v7.0.1,
  `astral-sh/setup-uv` v10.2.0).

## CI

The Linux CI (GitHub-hosted `ubuntu-latest`) now runs three jobs, and all
pass:

- Unit tests.
- Agent image build and its checks (`images/agent/build.sh` and `test.sh`).
- The network-isolation harness against real Docker: 38 checks pass in
  strict and open mode.

## Upgrade

```sh
git pull
uv tool install -e ./cli --reinstall
agentbox --version   # agentbox 0.1.1a0
```

Run `agentbox doctor <profile>` for each profile after the upgrade.

## Known limits

- Tested on macOS (Intel) with Docker Desktop and in Linux CI. Interactive
  Linux use is not tested yet.
- On Linux, use the 1Password (`op`) secret backend. The macOS Keychain is
  not available.
- Read [docs/SECURITY.md](../SECURITY.md) for the accepted risks, especially
  "Running host tools in a mounted folder".
