# agentbox 1.0.0

This is the first stable release. It replaces 0.1.1-alpha.

Release 1.0.0 does not mean that every path is tested live. Read "Tested
paths" before you use a path that the maintainer has not used.

## Tested paths

**Tested live** on the maintainer's host (macOS on Intel, Docker Desktop),
with real accounts and daily scheduled jobs:

- Claude Code in the box: interactive sessions and headless runs
  (`agentbox run`).
- Scheduled agent jobs and command jobs with launchd. A job starts Docker
  Desktop when Docker is not running.
- The MCP gateway with servers that use a bearer token or no
  authentication.
- The egress allowlist, `agentbox denied`, and `agentbox doctor`.
- The macOS Keychain secret backend.
- Scheduled-run notifications to a Slack incoming webhook.

**Tested in CI only** (GitHub-hosted `ubuntu-latest`):

- Unit tests, including the `examples/news-brief` tests.
- Agent image build and its checks.
- The network-isolation harness against real Docker (strict and open mode).
  The `ollama-gate` checks use a fake upstream, not a real Ollama.

**Not tested live.** These paths have unit and harness tests, but no real
end-to-end run:

- Codex and Pi in the box (login, sessions, MCP tool calls, Codex `/apps`).
- `git push` from the box with a `GH_TOKEN` secret.
- MCP servers with OAuth (`agentbox mcp login`, token refresh, `logout`).
- Inference through `ollama-gate` with a real host Ollama.
- Remote models through the router (for example Modal vLLM).
- The 1Password (`op`) and `env` secret backends.
- Interactive use on Linux.

**Not supported:** Apple Silicon. The images are amd64 only.

Report a problem on these paths as an issue.

## New

- **Command jobs.** `agentbox run <profile> --cmd-file F` and
  `agentbox schedule add <profile> --cmd-file F` run a shell script in the
  box with no agent. A command job has the same lock, timeout, run record,
  and isolation as an agent run. Bash reads the script on stdin with
  `-euo pipefail`.
- **Scheduled-run notifications.** Store the webhook URL as a shared
  secret (`agentbox secret set --shared SLACK_WEBHOOK_URL`). Then set
  `notify_webhook_secret = "SLACK_WEBHOOK_URL"` in
  `~/.config/agentbox/config.toml`. The value is the secret name, not the
  URL. Read "Notifications" in [docs/USAGE.md](../USAGE.md#notifications).
  Each scheduled fire then posts one line
  to an incoming webhook (Slack format): profile and job, status, exit code,
  duration, and the last transcript line. The webhook URL is a host-only
  secret: it never goes into a box. A failed post does not change the exit
  code of the fire.
- **Example project.** `examples/news-brief/` is a guided daily news brief.
  It uses the shared Claude token, profile secrets, the MCP gateway, the
  egress allowlist, headless runs, a schedule, and `doctor`.
- **Architecture diagram.** `docs/assets/architecture.svg` shows the
  storage layout, the runtime topology of one box, and cloud portability.

## Fixes

- **No Claude Code login picker in the box.** `agentbox up` marks Claude
  Code onboarding done. Before, `agentbox claude` showed the login picker
  although the shared token was valid.
- **No plugin marketplace denials.** The image blocks the Claude Code
  plugin marketplace auto-install with a managed policy. Before, each
  interactive start added denied requests to `agentbox denied`. Plugin and
  marketplace installs in the box are now refused by policy.
- **Isolation harness.** An `ollama-gate` refresh error before the first
  refresh no longer fails check 15 in CI.

## Changes

- Agent tool versions are updated (`images/agent/versions.env` and the
  `pi-mcp-adapter` lockfile).
- Commits on `main` must be signed. Release tags are signed from this
  release on.

## Upgrade

```sh
git pull
uv tool install -e ./cli --reinstall
agentbox --version   # agentbox 1.0.0
```

Image tags are content hashes, so the next `agentbox up` builds the new
images. The onboarding and marketplace fixes take effect only in a new
container. For each box that is running, end all sessions in the box first
(or run `agentbox down <profile>`). Then run `agentbox up <profile>`. The
new container replaces the old one and ends any session that is still
open.
Then run `agentbox doctor <profile>` for each profile.

## Known limits

- `run` and `schedule` record the exit code of the agent CLI only.
  `claude -p` can exit 0 when the task fails.
- `schedule add --force` removes the old job before it installs the new
  one. If the install fails, the old job is gone.
- `agentbox update` updates only the agent image pins. Sidecar image
  digests and the gateway lockfile change by hand.
- On Linux, use the 1Password (`op`) secret backend. The macOS Keychain is
  not available.
- Read [docs/SECURITY.md](../SECURITY.md) for the accepted risks, especially
  "Running host tools in a mounted folder".
