# agentbox 1.2.1

This release stops agentbox images from filling the Docker disk. On
2026-10-28 superseded agentbox images and build cache filled the Docker
Desktop VM disk (64 GB), and another stack's database did not start
(containerized-006).

## New

- **Image pruning** (PLAN §2.10). Every successful `agentbox update`
  (also when all pins are current), `--python-patch` and `--python-line`
  update, and every daily patch run that does not fail, removes
  superseded agentbox images. It keeps the current image, one previous
  image (the rollback target), the derived images of both, and every
  image that a container uses (running or stopped). It removes only tags
  that agentbox makes, and never uses `-f`. Then it runs `docker builder
  prune --force --filter until=24h`. Volumes are not touched.
- `agentbox update --prune [--dry-run]` runs the prune alone. `--dry-run`
  lists the tags and removes nothing.
- Freed space is measured as the used bytes of the Docker disk (`df` in a
  throwaway agent container: no network, no capabilities, `--pull never`).
  It is in the update record (`prune`, or `_update/prune.json`), in the
  applied Slack post (`; freed X.Y GB`), and in a `Docker disk:` line of
  the fleet report.

## Changes

- A failed update now also removes the tag of the failed candidate image,
  so it can never become the "previous" image.
- The update no longer prints the `docker image rm` line of unused images:
  it removes them.

## Tested paths

**Tested live** on the maintainer's host:

- `update --prune --dry-run`, then `update --prune`: 19 superseded images
  removed, every box image kept, a running box not affected. A second run
  removed 0 images and recorded the disk (29.9 GB used of 62.7 GB).
- The `df` measurement container.
- Real `docker image rm` output for a tag that is not the last one
  (`Untagged:`, no `Deleted:`) and for a missing tag.

**Not tested live:** the prune inside a real `--python-patch` or full
`update` run, a refusal (`conflict`) from `docker image rm`, and the
rollback removal of a failed candidate.

**Known limit:** about 5.9 GB of old build cache stays after the prune;
no `builder prune` form (`until`, `--all`, `--max-used-space`) removes
it. It does not grow with each rebuild.

## Upgrade

```sh
git pull
uv tool install -e ./cli --reinstall
agentbox --version   # agentbox 1.2.1
agentbox update --prune --dry-run
```
